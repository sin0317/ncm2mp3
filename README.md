# NCM → MP3 + SRT

在浏览器里把网易云客户端的 `.ncm` 文件解密成可播放的 **MP3 / FLAC**，歌词能一起转成 **SRT 字幕**。

**纯离线**：没有后端、没有 CDN、没有统计脚本，页面不发任何网络请求。文件不上传，断网可用，也可以存成单个 HTML 双击打开。

在线使用 → **https://sin0317.github.io/ncm2mp3/**

## 能做什么

| | |
|---|---|
| `.ncm` → 音频 | 本地 AES-128-ECB + keybox 解密，输出 MP3 / FLAC / WAV / M4A（按文件头魔数判断真实格式，不只看元信息） |
| 歌词 → `.srt` | 拖入同名 `.lrc` 会自动配字幕，也可以粘贴 LRC 文本手动生成 |
| 批量 | 一次拖多个文件，逐个出卡片，可试听、单独保存 |
| 元信息 | 歌名、歌手、专辑、码率、时长、封面、网易云歌曲 ID 都从文件里读出来 |

## 为什么不做「输入歌曲 ID 直接下载」

那一步绕不开服务器：要带你账号的会员权限去换音频直链，而 `music.163.com` 的接口既没有 CORS 头、也不支持 JSONP，浏览器直连拿不到数据。所以按 ID 下载做成了联网版（本地 / 云端各一份），本仓库只承担**完全离线**的那一半 —— 处理你**已经下载到本机**的文件，不碰任何账号凭据。

## 技术要点

- **AES-128-ECB 是手写的**。浏览器 Web Crypto 不支持 ECB 模式（`crypto.subtle` 只给 CBC/CTR/GCM），所以这里带了一份纯 JS 的 AES-128 实现，并用 NIST 标准测试向量校验过。
- **密钥表容易写错**。NCM 的 meta key 是 16 字节，其中第 9 个字节是反斜杠、最后一个是左括号，网上流传的字符串版经常少一位，直接当字符串用会报 key length 错误 —— 这里按十六进制字节定义。
- **LRC 时间标签的毫秒段是厘秒**。`[00:05:20]` 里的 `20` 表示 200ms 而不是 20 秒，按秒算会让整条字幕偏移。
- **制作信息过滤用词表而非泛化规则**。「短标签 + 冒号」这种规则会把「他说：你好」这种歌词正文一起删掉，所以只认作词/作曲/混音/小提琴这类具体标签，宁可漏几行署名。
- 最后一句字幕的结束时间会卡在音频总长，不会拖到文件之外。

## 本地开发

```bash
node build.mjs        # 把 ncm-core.js + lyric.mjs + 模板打成 dist/index.html
```

源码：`src/template.html`（界面与交互）、`../ncm-core.js`（解密核心）、`../lyric.mjs`（LRC → SRT）。构建脚本会检查产物里没有任何外部资源引用。
